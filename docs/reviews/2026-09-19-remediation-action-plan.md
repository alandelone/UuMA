# UuMA 工程评审修复行动方案

日期：2026-09-19

状态：六项修复已在本地实现并通过回归验证；尚未部署，也不代表阶段已获批准。

依据：[工程标准评审报告](2026-09-18-agent-engineering-review.md)

## 目标与范围

修复评审中已复现的六项控制面漏洞，并用回归测试证明它们不能再次发生。无需重写整个 UuMA。优先收紧授权和状态转换，再修复并发一致性，最后接入独立完成验证。

保留现有数据和事件历史。控制状态继续属于 `uuma.db`，知识状态属于 `wisdom.db`，不改用或合并 Hermes `state.db`。本方案只记录实施工作，不授权部署或批准 mission gate 转换。

## 按顺序执行的六项修复

| 顺序 | 对应发现 | 具体行动 | 验收条件 |
| --- | --- | --- | --- |
| 1 | R1：Worker 自审批 | 服务端按变更类型、目标与可信身份决定审批要求；Worker 只能提交提案，不能通过 `requires_user_approval=false` 自动应用共享图变更。 | Worker 尝试绕过审批被拒绝或保持待审；共享图不变；合法审批路径仍可用。 |
| 2 | R3：心跳写入终态 | 心跳仅更新进度字段或明确允许的非终态；`COMPLETED / FAILED / CANCELLED` 经专门的状态转换入口写入。 | 心跳不能绕过结果验收；拒绝请求不产生终态事件；合法终态转换保持 Task 与 Run 一致。 |
| 3 | R2：版本检查与提交分离 | 将读取当前版本、校验版本、追加事件和更新投影放进同一数据库事务；正确性相关写入必须提供预期版本。 | 两个提案基于同一版本时仅一个成功，另一个明确返回冲突；不能静默覆盖。 |
| 4 | R4：旧 Run 回退 Task | Task 持久化当前有效 Run 和执行代次；注册、重试、接管有明确前置条件；更新事务检查当前 Run、版本和代次。 | 新 Run 完成后，旧 Run 的迟到进度、阻塞或结果不能改变权威 Task 状态；重启后约束仍有效。 |
| 5 | R5：幂等创建竞态 | 将作用域、幂等键和请求摘要存入可约束字段；数据库唯一约束配合事务内原子认领；相同请求返回原任务，不同请求复用同一键返回冲突。 | 并发提交相同请求只创建一个 Task；重试返回同一 task_id；不同内容不能误用已有任务。 |
| 6 | R6：Worker 自证完成 | Worker 提交结果后进入 `REVIEW` 或等价待验证状态；独立检查器或用户针对冻结的验收条件和结果摘要审核证据，再经受控入口完成任务。 | Worker 自报 `passed=true` 不足以完成任务；验证记录与验收项、结果版本、产物和审核身份绑定；结果变更使旧验证失效。 |

## 实施位置与交付物

主要涉及 `src/uuma/service.py`、`models.py`、`event_store.py`、`projections.py`、`mcp_worker.py`，以及相应 Control MCP、HTTP API 和 Hermes 接入路径。

1. **数据库迁移**：增加幂等字段、请求摘要、当前 Run、执行代次和必要版本字段。迁移前检查已有重复键及多 Run 状态；遇到歧义应显式报告并安排人工处理，不能静默删除或覆盖记录。保证历史事件仍可重建投影。
2. **服务端与接口修改**：统一授权、版本检查和状态转换的事务入口；客户端传入的审批布尔值不能成为授权来源。同步更新接口合同，明确冲突与权限错误语义。
3. **独立验证记录**：保存验收条件版本、结果摘要、产物引用、检查结果、审核身份和时间。自动检查适用于可机械验证条件，其余进入用户审核。
4. **回归与集成测试**：将六项缺陷复现转成安全断言；增加并发、重复投递、迟到结果、迁移和重启恢复测试。
5. **验证报告**：记录测试命令、结果、迁移影响、剩余限制及 Hermes 集成证据；由用户或 Orchestrator 决定是否批准阶段转换。

## 实施阶段

### 第一阶段：封住绕过路径

完成第 1、2 项。优先禁止 Worker 自审批和心跳写终态，同时保留正常提案、进度与结果提交功能。

### 第二阶段：保证共享状态一致性

完成第 3–5 项。版本校验、幂等认领、当前 Run/执行代次判断、事件与投影写入必须在同一确定性提交边界内完成。不要仅给应用层增加一个进程内锁，因为多个 MCP 进程仍可能并发写入。

### 第三阶段：完成必须有独立证据

完成第 6 项。明确哪些验收由自动检查器完成，哪些必须用户审核。Worker 可以提出结果与证据，不能自行定义验收、审核自己并发布权威完成状态。

## 六项修复之后的生产门槛

这些工作需另行设计与验收，不能因为六项漏洞修复就视为自动满足：

- **任务合同与预算**：明确允许/禁止范围、步骤、时间、token、费用预算和停止条件，并在实际执行路径计量与阻断。
- **超时与取消**：让取消传递至实际执行端；对可能已产生外部副作用的超时先记录 UNKNOWN 并查询结果，避免盲目重试。
- **外部副作用一致性**：按实际业务接入稳定幂等键、Effect Ledger、必要的 outbox、补偿与人工调和路径。
- **故障注入**：验证协调器崩溃、旧 Owner 恢复、ACK 丢失、重复/乱序消息及补偿超时下的不变量。
- **生产收益与运行证据**：补充单 Agent 对照、质量/成本/延迟指标，以及可关联任务、执行、状态和副作用的观测证据。
