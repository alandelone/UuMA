## 可以怎样使用

| 你说的话 | honc 应做的事 |
|---|---|
| 今天流鼻涕，有点累 | 保存原话；没说的部位、评分、精确时间保持未知，不追问变化 |
| 今天精神很好 | 同样作为身体状态保存，不要求一定有不适 |
| 今天锻体20，单位没提供 | 保留旧数字及未知单位，不猜成20次或20分钟 |
| 今天运动20分钟 | 匹配已有习惯及其单位；旧习惯单位不明确时保留这次明确的分钟，不暗改旧定义 |
| 早餐习惯做了 | 只对应早餐；不一起完成午餐、晚餐 |
| 还没运动，明天再做 | 不写成完成；明确要求记录没做时使用 not_done |
| 记一下今天的日记：…… | 保存原文，并同事务关联一次日记习惯；不重复打卡 |
| 昨天的日记：…… | 作为补记，不取消今天的日记提醒 |
| 起床了／开始今天 | 记录明确事实；若早于08:00，推进同一天尚未发送的晨间提醒 |
| 准备睡了 | 若早于21:30，推进同夜尚未发送的睡前提醒，21:30不再重复 |
| 新增、改名、暂停、恢复、退休一个习惯 | 通过设置工具改版本；旧记录和回执保留 |
| 这个提醒改成两次，15:00和15:30 | 检查明确次数与发送时间，使用同一实例额度；重要度不额外增加次数 |
| 看上周的身体记录／更正那条数量 | 查询对应历史；更正保留原版本，统计使用有效版本 |

## 已确定的提醒行为

- 默认每个习惯发生实例提醒一次；同一习惯一天可有独立的早餐／午餐等实例。
- 同时到点的习惯合成一条通知，逐个保留额度和回执，重要度只改变排列。
- 起床兜底08:00，睡前兜底21:30，时区 Asia/Kuala_Lumpur。
- 只有起床后、睡前两类情境触发。厕所／休息模式不自动触发。
- 时间窗口含开始、不含结束；固定时间默认30分钟有效，错过则过期，不移到晚上追催。
- 明确完成可取消对应尚未发出的提醒；不撤回已发通知，不把不确定投递当作失败重发。
- 晚上只邀请写日记和记录今天身体状态；不追问身体变化，不汇总催打未完成习惯。
- 没回应不会增加提醒。定时器触发不等于用户已醒、已做或身体发生变化。

## 维护与恢复

生活数据只在 honc.db；控制运行仍在 uuma.db；不占用 Hermes state.db 或 Wisdom数据库。
使用原 Hermes Agent、插件、Skills、MCP和原生 no_agent 调度／投递队列。
每次配置修改有版本检查；每次事实写入有来源和幂等回执；不确定时查原回执，不盲目再写。
历史可按类型、习惯、日期查询，分页绑定同一快照；更正和撤销均保留旧版本。
工作回合与生活事实分开，身体记录和打卡不结束专注回合、不修改 Graph 项目结构。

安装前备份本次拥有的配置、手册和插件，并一致备份 honc.db。
需要回退时先暂停新增的原生调度，再恢复清单内的配置文件；保留新增历史，
不可用旧数据库覆盖上线后新的用户记录。备份路径见安装回执。
模型、账户凭据和其他代理的配置不随本功能改变；新工具在新会话／运行实例边界加载。
