# Catalog list responsiveness and source-verification boundaries

The real migrated Catalog copy contains3177papers, of which1197are visible in the ordinary list and1980are quarantined. The v64 in-process HTTP readback reached its first1000-row page and remained live while reading PDFs. A separate bounded read-only diagnostic, v79, captured `paper_presentation -> require_pdf_source -> pathlib.open`; it reached row16 in17.53seconds. The original verifier's Python process had read approximately1.3GB at the earlier observation. This is evidence of physical-source work in list rendering, not a completed HTTP acceptance result.

`paper_presentation` unconditionally verifies the full PDF, even for papers with no initial reading. Published understanding, active reading reconciliation and deep progress can also revalidate source bytes. Repeating physical-source verification across an entire list or before Theme filtering makes metadata browsing perform substantial file I/O. The full source validator remains necessary at actual reading and evidence-use boundaries.

The next implementation must make the distinction explicit:

- List cells describe retained, source-bound reading snapshots, candidate Themes and recorded job state. They must state when physical source integrity has not been rechecked. A matching registered file version alone cannot become `source_current=true`. A known version mismatch remains false; an unchecked physical file is unknown.
- Listing, filtering, sorting and counting papers must not open and hash every PDF. Multi-Theme membership, roles, review status, open unmapped candidates and distinct-paper aggregation must retain their existing semantics.
- The original full-PDF and exact-source checks remain mandatory before initial or deep reading, source-bound model dispatch, scientific publication, and explicit evidence/detail operations. No abstract-only fallback, fabricated integrity status, implicit deep consent or scientific approval is permitted.
- Historical understanding must retain its original source version and provenance. A list snapshot is distinct from a fresh source check; it must neither silently claim current eligibility nor erase retained history because a physical source is unavailable.
- Manual reading keeps priority, and all automatic reading/parsing/backfill remains in00:00-08:00Asia/Kuala_Lumpur. Metadata rendering cannot enqueue work or reset paused, stopped or quarantined records.

Implement this as a separately tested successor to the frozen evidence-completion release. Keep the actual ongoing original-paper workflow pinned to its tested engine. Verify the real3177-paper copied database, all1197visible IDs and quarantine exclusion, the new list cells, multi-Theme filtering, read-only preservation and zero physical PDF reads during list rendering. Retain negative tests proving that explicit evidence/detail use and actual workers still reject missing, changed, mismatched or unreviewed sources. Then perform real browser acceptance and complete regression before production activation. The v64 slow readback and v79 diagnostic must remain preserved; neither is a passing substitute for these checks.

Source inspection identifies four additional boundaries beyond the unconditional PDF check in `paper_presentation`: `CatalogUnderstanding._paper` verifies parsed sources; `catalog_skeleton_themes._verified` loads a full native snapshot; `CatalogReading._reconcile_one(enqueue=False)` can verify a parsed PDF; and `catalog_deep_presentation.progress` verifies each job's parsed source. A list-mode fix must cover all of them without routing real workers, model payload admission, source corrections or publication through the snapshot path. Stored content IDs and JSON integrity, registered source IDs, identity-review epochs, quarantine, review events and purpose bindings can still be checked from the database. Physically unchecked source eligibility must remain unknown rather than true.

The existing Chinese interface uses `detail.source_current` to enable deep-reading requests, and currently renders an older-PDF warning for any falsy value. Update the interface to distinguish explicit false from unknown. Opening a paper's details should fetch the strict source-checked detail projection before enabling its existing deep-reading action. A list snapshot must not turn unknown freshness into either a stale-PDF diagnosis or permission to execute deep reading. Preserve the interface language and the original candidate/review/source-version distinctions.
