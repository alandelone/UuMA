## 已确认的范围变更

- 本阶段只连接当前 Windows 工作站与服务器。另一台 Windows 延期；已有安装包保留，不作为本阶段完成门槛。

- ChatGPT 云端 Chat 对话及换账户后的历史保留纳入目标；不能只备份本地 Work/Codex 文件。
- Phoenix 的持久化追踪记录是明确的新增归档来源。它不能替代原始对话、项目文件或领域数据库。
- 继续保留每天午夜一次、历史版本不因源删除而丢失、后台限速、A2A 协作和只读 MCP 的既定要求。

## 全范围恢复的完成标准

这里的“全范围”指本阶段来源登记清单中的当前工作站和服务器资料，加上用户现已纳入的云端账户资料；不是两台 Windows，也不是所有理论上存在但不可访问的数据。先做来源对账，不能靠只登记几个来源把目标缩小。

1. **范围闭合。** 每个已知目标路径、数据库、对话集合、追踪存储和附件根目录都有归属与状态；明确已覆盖、EMPTY、未采集、不可访问、截断、延期。未解释缺口不得计为完整。
2. **选定恢复点并全量校验。** 固定源清单、批次/修订、时间和版本。对本次纳入的全部清单及加密对象执行摘要、大小和历史链校验。多来源快照注明各自采集时间，不伪称跨系统原子快照。
3. **真正隔离全量恢复。** 把所选恢复点的全部对象恢复到新的隔离目录，逐文件核对清单及可用的明文摘要；无原明文摘要时建立另外的可信验证依据，不把密文校验冒充明文一致。不得覆盖生产目录。
4. **数据库和关联可用。** SQLite 执行 integrity_check；按各自引擎验证其他存储。逐来源核对关键记录数量/标识、图节点边、历史状态、附件引用和重建所需输入。控制库、Wisdom、Hermes 原生库及各领域库保持独立。
5. **历史确实可恢复。** 对每个有历史的来源验证最新及至少一个较旧恢复点；在隔离夹具证明源修改/删除后旧版本仍能恢复。没有历史的来源明确说明，不能捏造第二版本。
6. **独立性与权限。** 使用独立导出的恢复密钥；在不能访问原源目录、原 DPAPI 用户及原运行服务时仍可恢复。私密恢复资料与普通 agent 可读索引保持权限边界。
7. **可阅读、可查询。** 原始对话保留消息顺序、身份、时间、分支与已有附件；项目及 agent 记录保留原引用。对声明已索引的来源，通过 Librarian 实际查询得到正确来源与版本。Phoenix 验证 trace/span 关联；Notion 验证页面身份和版本时间。
8. **不会重放副作用。** 隔离恢复不自动启动定时任务、提醒、机器人收发、模型重试或外部写入；恢复的数据保留原待审阅、暂停、失败及未决定状态。
9. **交付可复现证据。** 提交逐来源 PASS/PARTIAL/FAIL/BLOCKED 矩阵、恢复命令/版本、所用批次及摘要、耗时/峰值资源、实际结果和缺失项。存在未接受的 PARTIAL/BLOCKED，就不能把该来源计作全范围验收通过。

恢复耗时目标 RTO 目前未被用户量化；首次演练先报告实测值，不虚报 SLA。日备份稳态目标与初始化完成条件需分开列明。

## 下一执行者的交付边界与顺序

1. 先完成来源登记与差异清单，尤其 Phoenix、云端 Chat、项目文件、Notion 两个错误及新 NAS 身份；保持另一台 Windows 延期。
2. 复用现有上线组件，补缺失的来源采集/增量历史与目录发布。先确认当前活跃版本和历史，不重建迁移后的生产库。
3. 恢复新 NAS 发布并回读验证；完成声明范围的可读目录与权限验证。若共享 gateway 需重启，遵循既有空闲边界与发布回执要求。
4. 执行隔离全量恢复及历史/独立密钥验证；最后交付逐来源矩阵及待用户审阅结果。

不要以服务 active、注册来源数、单个恢复样本、MCP 工具数或对话列表数量代替完整验收。不要无条件声称能取得已删除、无权限或接口从未返回的数据。
