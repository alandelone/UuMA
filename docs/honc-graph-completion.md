# honc 完成报告自动同步 Project Graph

2026-10-20，Asia/Kuala_Lumpur。

## 用户确认的行为

用户要求：在 honc 明确说“我今天完成了这个东西”，对应 Project Graph 任务也应自动勾选完成。
核查发现旧路径只有生活记录和一般执行账本，Graph 地址未配对，任务上下文没有读取最新节点。

进一步检查，真实 Graph 的 307 个 ACTION 中 304 个没有填写完成标准。用户明确选择：
**“否，先补完成标准再勾选”**。因此缺少 `done_when` 是后端阻断条件；本次不批量生成标准，
不替用户把旧任务标为完成，也不改变项目层级、角色或优先级。

## 使用方式

- “今天完成了〈Graph 中的完整任务名称〉。”
- “任务〈任务ID〉已经完成。”
- 已关联当前专注任务时：“这个任务完成了。”

宿主核实真实 Telegram／本地输入后，直接处理完成同步，不靠模型重新编造完成凭据。
文字和已认证语音转写都支持；同名、无法唯一关联时先问具体任务。
当前匹配采用明确 ID、完整任务名或当前专注任务，不使用模糊关键词猜任务。
否定、计划、疑问、转述、部分完成和不确定表达不勾选。

没有标准时，回复保留完成报告、尚未勾选；先让 Yonc／用户补好任务标准，再报告完成。
仅报告普通进度仍存 honc；习惯、身体和日记继续走原有生活记录，不写成项目完成。

## 实际实现

`integrations/hermes/honc_life` 已认证入站消息
→ `WorkCompletion.report` 获取 Graph 数据库身份和最新图
→ 唯一匹配已接受的普通 ACTION 叶子，检查标准／复核／归档／Parked
→ honc 专用账本保存原始来源、执行事实、任务快照和 `USER_REPORTED` 评估
→ 原有 Graph `/api/v2/execution/action-decisions`
→ 校验 ExecutionReceipt，并读回节点确为 `DONE`
→ 才回复“已勾选完成，并已读回确认”。

完成依据是用户的明确报告，保留原文、来源消息 ID、任务 ID、标准快照和原回执；
不把它说成系统独立验过文件或测试。现有 `AssessmentResult` 增加 `USER_REPORTED` 值，
没有新增表或数据库合并。角色未设置的明确旧任务允许同步；已经 PARKED 的任务仍需复核。

写入绑定当前 Graph 数据库身份，采用版本检查及不超过 36 字符的稳定操作编号。
同一输入重试先查原回执，避免重复事件／勾选。结果丢失时保留 outbox，现有一分钟生活
调度会静默对账；不新增调度任务或通知。已知版本／身份冲突保留为 `CONFLICT`，不盲目
覆盖；撤回或重新打开的节点不会被旧回执重新勾选。

`honc_get_context` 现在优先读取最新 Graph 节点并保存快照；连接异常时标明缓存和错误。
模型的另行 `honc_apply_completion` 路径被当前消息宿主阻止，防止重复或伪造来源。
后续生活配置部署保留 `work_completion`，原习惯／提醒／日记配置不重置。
