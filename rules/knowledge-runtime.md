# Knowledge specialist runtime boundary

Scholar and Wisdom-Oldman require their own graph before domain tools, knowledge answers,
and completed results. The semantic Worker preflight validates bridge identity, registered
project/namespace, required schema and an actual graph-store read. Empty data is allowed;
unavailable graph storage is not. Service recovery cannot bootstrap a missing graph, change
schemas, approve candidates or claim that evidence exists.

Keep graph services independent of individual MCP connection lifetimes. On Windows the MCP
SDK Job Object kills direct descendants when its connection closes, even with detached process
flags. Use the owned hidden runtime launcher, which passes environment through stdin rather
than command arguments or temporary credential files. Hidden Python bridges need usable logging
streams; use matching python.exe with the window hidden, not pythonw.exe without streams.

Wisdom idle shutdown must preserve shared Docker services while a Scholar bridge is present.
Do not interpret a listener or configured project ID alone as proof that graph storage works.
Runtime acceptance includes checking liveness after the verification MCP client has exited.
