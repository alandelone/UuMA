# Antigravity bridge runtime verification

Keep the bridge token outside Git with current-user/SYSTEM ACLs. Authentication
must stay mandatory. A successful interactive launch is not proof of scheduled
launch readiness. Preserve startup errors and verify token access in the actual
scheduled child context before promoting the API deployment. Never print token
contents. Reconcile file visibility errors rather than removing authentication.

Task Scheduler can finish stopping its action before the supervisor releases its
mutex. Wait for both, and use a kill-on-close Windows process job so forced task
stops cannot leave the bridge or SSH tunnel behind. Only stop verified owned
processes. Recheck the real tunnel and model call after the context fix; keep the
previous successful model call instead of replaying it for bookkeeping.

Use the project logs/antigravity-bridge service state directory when the native
scheduled context and interactive AppData path resolve to different directory
identities. Verify the actual child can read its protected token there. Keep the
folder ignored by Git and preserve the same current-user/SYSTEM token ACL.
